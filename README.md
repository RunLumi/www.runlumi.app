# Lumi website

Bilingual Astro website for [runlumi.app](https://runlumi.app), deployed as an Astro SSR application on Cloudflare Workers.

For production architecture, routing, secrets, deploy procedure, and the
currently handled failure modes, read [DEPLOYMENT.md](./DEPLOYMENT.md).

## Dependency install policy

npm 11 resolves version ranges through a release-age filter (`--before` / `min-release-age`), and the npm wrapper on Lumi dev machines injects a 7-day window into every `install`, `ci`, and `update`. Fresh resolution of a package published within the last few days fails with `ETARGET ... with a date before ...` even though the version exists. Because CLI flags take precedence over project `.npmrc`, this cannot be overridden from the repo — the guardrail is lockfile discipline:

- **Install from the lockfile.** Run `npm ci` for setup and CI. `npm ci` never re-resolves version ranges, so the age filter can neither fail nor change the dependency tree.
- **The lockfile is the source of truth.** Commit `package-lock.json` changes. With a complete lockfile, even `npm install` is a no-op (verified: zero drift); the filter only bites when npm must resolve a range — new or bumped dependencies.
- **Adding or upgrading a dependency:** resolve explicitly with a fresh window, then commit the lockfile:

  ```bash
  PKG_MIN_AGE_DAYS=0 npm install <package>
  ```

- **Machine-level guard:** `PKG_AGE_BYPASS=1` disables the injected window entirely (it prints a warning). Do not wire it into scripts; keep it for one-off maintenance.
- **`npx` is blocked without `--no-install`** by the same wrapper. Use package scripts (`npm run ...`) or `./node_modules/.bin/<tool>`, or pass `--no-install` to run a binary already in `node_modules`.

## Routes

Public:

- `/` — English landing page, prerendered
- `/vi` — Vietnamese landing page, prerendered
- `/jobs` — public careers index
- `/jobs/[slug]` — role detail + application + work sample

Hiring admin:

- `/admin/jobs` — jobs
- `/admin/jobs/[id]` — role editor + application test builder
- `/admin/jobs/applications` — candidate pipeline
- `/admin/jobs/applications/[id]` — full application review, files, notes, history

## ATS architecture

- **Astro + Cloudflare Workers** — SSR for dynamic hiring pages; landing pages remain prerendered.
- **D1** — jobs, test questions, applications, answers, stages, notes and audit events.
- **R2** — private CVs and candidate-uploaded work samples. Candidate files never receive public R2 URLs.
- **Signed admin session** — HMAC-signed HttpOnly cookie using Worker secrets.
- **Optional Cloudflare Access** — recommended as a second layer in front of `/admin/jobs*` and `/api/admin/*`.

The public apply flow works without client JavaScript.

## First-time Cloudflare setup

Install dependencies:

```bash
npm ci
```

Create the D1 database:

```bash
npx wrangler d1 create lumi-jobs
```

Copy the returned database UUID into `wrangler.jsonc` under `d1_databases[0].database_id`.

Create the private R2 bucket:

```bash
npx wrangler r2 bucket create lumi-job-files
```

Apply the schema:

```bash
npm run db:migrate
```

Set admin secrets:

```bash
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put ADMIN_SESSION_SECRET
npx wrangler secret put EMDASH_ENCRYPTION_KEY
```

Use a long random value for `ADMIN_SESSION_SECRET`.

For local development, create `.dev.vars`:

```dotenv
ADMIN_PASSWORD=local-only-password
ADMIN_SESSION_SECRET=local-only-long-random-secret
```

Then apply local D1 migrations and run Astro:

```bash
npm run db:migrate:local
npm run dev
```

## Deploy

Production is deployed manually from this repository with Wrangler. GitHub Actions
runs validation only; it does not publish the Worker.

```bash
npm run deploy
```

`npm run deploy` runs a preflight first (`scripts/preflight.mjs`), then builds and
invokes Wrangler to deploy the Worker. The preflight lists the Worker's
secrets and fails with a clear message if `ADMIN_PASSWORD` or
`ADMIN_SESSION_SECRET` are missing — without them the admin login silently
rejects every attempt.

The Worker entry point is generated by `@astrojs/cloudflare`. Static assets and the Worker deploy together. The primary public hosts are `https://runlumi.app` and `https://www.runlumi.app`; `landing.runlumi.app` remains a compatibility alias.

## Journal and EmDash

The public journal lives at `/blog` and `/vi/blog`. EmDash provides the editorial CMS at `/_emdash/admin`, with a dedicated `lumi-content` D1 database and `lumi-blog-media` R2 bucket. Its schema is checked into `.emdash/seed.json`; the public journal keeps reviewed fallback content in `src/data/blog.ts` so an uninitialized CMS cannot make the public archive empty.

The production Worker needs `EMDASH_ENCRYPTION_KEY` in addition to the ATS secrets. Generate it with `emdash secrets generate` and store it with `wrangler secret put EMDASH_ENCRYPTION_KEY`. Do not reuse the ATS session secret.

## Admin security

The app has its own signed admin session so it can run without an external identity product.

For production, also protect the admin surfaces with Cloudflare Access:

- `/admin/jobs*`
- `/api/admin/*`

Allow only Lumi hiring-team identities. Do not protect public `/jobs*` or `/api/jobs/*`.

## Candidate files

- CV: PDF, DOC, DOCX, max 10 MB.
- Test upload: PDF, Office documents, text/Markdown/CSV, spreadsheet, presentation, images or ZIP, max 15 MB each.
- Total uploaded payload accepted by the application endpoint: max 30 MB.
- Files are stored in private R2 and downloaded only through an authenticated admin endpoint.
- Deleting an application removes both D1 records and R2 objects.

## Development

```bash
npm run typecheck   # astro check (also runs as part of build)
npm run lint        # AGENTS.md policy checks (hype copy, remote deps, D1 blobs, locale peers)
npm run test        # node:test suites over src/lib (no test framework dependency)
npm run check       # alias for typecheck
npm run build       # astro check && astro build
```

The `lint`, `typecheck`, and `test` scripts are run by the ECC pre-push hook. Policy linter findings on deliberate lines can be suppressed with a trailing `// !# policy: <rule-id>` comment.

Tests use Node's built-in test runner with type stripping (Node 26+). The `cloudflare:workers` module — which only exists inside workerd — is resolved to a stub backed by `process.env` via `scripts/test-setup.mjs`, so `src/lib` modules are tested directly without a workers runtime.

Useful commands:

```bash
npm run cf:types
npm run db:migrate:local
npm run db:migrate
npm run deploy
```
